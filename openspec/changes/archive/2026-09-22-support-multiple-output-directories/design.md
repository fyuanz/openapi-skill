# Design

## Context

参见 `proposal.md` 的动机。当前 Node 配置公开类型将 `output` 表示为可选字符串，解析后保存一个绝对路径；`run()` 在完成一次输入读取和生成后只调用一次 `publishSkill()`，并返回单个 `skillDirectory`。`publishSkill()` 已为一个输出父目录提供完整树校验、暂存、备份、替换失败恢复和陈旧文件清理。

本变更要复用该单目录安全边界，同时使一次运行覆盖多个 Agent 的任意目录，而不把 Codex、Trae 等 Agent 名称写入产品模型。

## Goals / Non-Goals

**Goals:**

- 保持现有 `output: string`、默认目录和单目标调用结果兼容。
- 在读取输入和生成 Skill 后，将同一不可变文件集合独立发布到多个目录。
- 在开始下载和发布前识别无效、重复或存在结构冲突的输出配置。
- 对全部成功和部分失败提供稳定、可测试且不泄露源内容的结果。

**Non-Goals:**

- 不提供跨输出目录事务、两阶段提交或跨目录回滚。
- 不自动探测已安装 Agent，也不推断 Agent 专属默认目录。
- 不改变单个 `publishSkill()` 的目录所有权、校验和原子替换契约。
- 不让不同输出目标使用不同 `skillName` 或不同生成内容。

## Decisions

### 1. 公开配置接受字符串或有界数组

`OpenApiSkillConfig.output` 采用 `string | string[]`。配置解析阶段将省略值、字符串和数组统一为按声明顺序排列的绝对路径数组，并限制为 1 至 8 个目标。解析后的公开配置新增复数 `outputs`，同时保留 `output` 指向第一个目标，避免现有程序化调用方立即失效。

选择有界数组是为了与项目现有的输入、服务、文档和输出边界保持一致，并防止一次命令触发无界文件系统写入。没有采用 `outputs` 作为新的配置键，因为让 `output` 兼容两种形态可直接满足现有配置迁移；也没有同时支持两个键，以避免优先级和冲突规则。

### 2. 在任何 I/O 工作前完成多目标冲突校验

每个条目使用现有项目根目录和平台路径规则解析。规范化绝对路径不得为文件系统根目录；Windows 下比较键转为大小写不敏感形式，其他平台遵循各自路径语义。重复目标以及互为祖先/后代的输出父目录均被拒绝。

祖先关系限制比逐个等待实际冲突更保守，但可以防止某个目标的 `<skillName>` 或 `.openapi-skill` 状态树落入另一目标管理范围。没有采用 `realpath` 作为唯一判据，因为输出目录允许尚不存在；输出配置仍属于现有产品边界中的可信项目配置，单目标发布器继续负责生成树和既有 Skill 的所有权校验。

### 3. 生成一次，按声明顺序尝试所有发布

下载、校验和 Skill 生成仍只执行一次。生成完成后，对每个 `outputs` 条目调用现有单目标发布边界，并收集成功目录与目标级错误。某个目标失败后继续尝试其余目标，最终若存在任一错误则抛出一个结构化的多目标发布错误。

继续尝试比首错即停更符合“为多个 Agent 分发”的目标，并能在一次运行中给出完整诊断。代价是部分成功范围可能扩大；这是规格明确接受的非整体事务语义。未选择跨目录预提交和回滚，因为不同文件系统、权限和占用状态会使其无法可靠兑现全局原子性。

### 4. 复数结果为主，单数字段兼容

成功的 `RunResult` 新增 `skillDirectories: string[]`，并保留 `skillDirectory: string` 作为第一个目标的兼容字段。服务数、文档数和 `fileCount` 仍描述只生成一次的 Skill，不随目标数倍增。CLI 成功消息列出全部目录。

部分失败使用专门错误携带按声明顺序排列的目标状态，交由现有诊断层输出安全摘要并返回退出码 1。目标标识采用已规范化输出路径或最终 Skill 目录；错误格式化不得包含 OpenAPI 文本或来源 URL。程序化调用通过捕获该错误获得部分成功信息，而不是返回一个看似成功的 `RunResult`。

### 5. 版本和文档同步到 2.1.2

更新 `package.json`、锁文件和版本断言到 `2.1.2`。中英文 Node README 记录数组示例、1 至 8 个目标限制、逐目录原子以及部分成功不回滚。受影响的 `docs/codex/` 项目事实、任务状态和技术决策在实现时同步更新；Java 坐标不随此 Node-only 补丁变更。

## Risks / Trade-offs

- [部分成功造成 Agent 间短暂版本差异] → CLI 以失败退出并列出各目标结果，允许用户修复失败目标后重跑；成功目标不会被回滚。
- [同一路径的符号链接别名可能绕过词法去重] → 明确输出配置是可信输入，拒绝可确定的规范化重复与嵌套关系，不以要求目录预先存在为代价强制 `realpath`；单目标发布仍校验既有 Skill 的生成器所有权。
- [兼容字段长期造成 API 冗余] → 在本补丁中明确复数字段为新代码首选，单数字段仅保持兼容，不在补丁版本中删除。
- [多个目标放大发布耗时] → 下载和生成只执行一次，仅重复必要的目录验证与写入；8 个目标上限约束最坏情况。

## Migration Plan

1. 先以失败测试固定字符串兼容、数组解析、冲突拒绝、全部成功和部分失败行为。
2. 增加规范化复数目标和发布编排，不改变单目标发布器的外部行为。
3. 更新返回类型、诊断、CLI 文案、版本元数据和中英文文档。
4. 运行 Node 全套测试及打包检查；若需回退，可恢复单目标编排和 `2.1.1` 元数据，现有字符串配置无需迁移。

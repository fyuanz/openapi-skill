# Design

## Context

见 proposal.md。现有生成器已解析契约并计算引用闭包，Java 聚合还接受磁盘上的旧服务树。发布校验器依赖 JSONL 和旧导航结构。此次跨 Node/Java、涉及迁移，需要显式设计。

## Goals / Non-Goals

**Goals:** 索引一次检索后直达契约；单/多服务同构；保留准确契约及确定性。
**Non-Goals:** 不增加在线搜索、向量数据库、运行时依赖或索引分片；不发布 npm。

## Decisions

- 将布局投影与契约解析分离：以生成的契约及机器索引为事实源，集中分配扁平路径、重映射链接并渲染总索引。旧服务格式只作为内部/迁移输入，最终只输出 v4。
- 路径为 references/{operations,schemas,refs}/service--document--name.md。使用确定性摘要处理超长/冲突，文件名限制在 120 个 ASCII 字符内；完整身份仍在索引及契约中。
- 只重写生成 Markdown 的链接，不改 fenced JSON 中的原始描述、示例或 $ref。所有契约引用、closureFiles 和机器索引统一映射。共享 conventions 保持一份。
- 每个接口检索记录独立包含来源和全部检索线索。空文档保留明确记录。机器索引位于 references 根供验证/程序使用，Agent 只需 Markdown 索引。
- v4 发布校验验证索引覆盖、路径深度、引用闭包、来源及导航可达；旧版本继续按旧规则验证后替换。Java 聚合接受新旧输入。
- 按用户要求 Node 版本升至 2.2.0，Java Maven 坐标不在本次发布。无需同时保存旧导航输出。

## Risks / Trade-offs

- [目录改动破坏旧消费者路径] → 按用户要求发布 2.2.0，明确迁移说明，旧输出通过完整原子替换清理。
- [链接重写损伤来源文本] → fenced JSON 不做文本替换，测试恶意 Markdown 和递归引用。
- [命名跨平台冲突/长路径] → ASCII 有界命名和大小写碰撞验证。
- [总索引较大] → 单行记录支持搜索，预算不足明确失败，不截断。
- [双实现漂移] → 共享 fixture 的路径与导航行为测试。

## Migration Plan

先建立失败测试，再实现布局及校验，更新回归断言和文档，运行 Node/Maven 完整测试及 npm 打包预检。提交并普通 push；用户手动 npm publish。回退使用旧版本在独立输出目录重新生成。

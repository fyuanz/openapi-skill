### 环境备注（补充）
- **Maven 必须走 Windows 原生路径**：从 Git Bash 直接调 `mvn` 会报
  `ClassNotFoundException: org.codehaus.plexus.classworlds.launcher.Launcher`。
  可用方式：`"$JAVA_HOME/bin/java" -classpath "D:\apache-maven-3.9.16\boot\plexus-classworlds-2.11.0.jar"
  "-Dclassworlds.conf=..." "-Dmaven.home=..." "-Dmaven.multiModuleProjectDirectory=<项目根>"
  org.codehaus.plexus.classworlds.launcher.Launcher -B spring-boot:run`。
  注意 classworlds jar 版本要按 boot/ 目录实际文件名（本机 2.11.0），且必须带
  `maven.multiModuleProjectDirectory`，否则报该属性未设置。
- 本机 PowerShell 工具**会拦截** `Start-Process` 启动 `mvn.cmd`/`cmd.exe`（安全策略），且其 stdout 常不回显；
  长时间服务进程用 Bash 工具的 `run_in_background` 直接前台运行更可靠。
- Vite dev server 只绑 `localhost`（含 IPv6 `::1`），用 `127.0.0.1:15173` 访问会 502，**要用 `localhost:15173`**。
- Git Bash 的 curl `-F`（multipart）在本机不可用（status 000），验证 multipart 要改用 Node 的 `fetch`+`FormData`。
- Node 里 `/tmp/...` 路径会解析成 `F:\tmp\...`；临时脚本要写到项目内再用相对路径。
- SpringBoot testbed 的 `application.properties` 里 `server.port=18080` 会被测试随机端口覆盖，
  手工跑 `spring-boot:run` 时用 `-Dspring-boot.run.arguments=--server.port=18080` 固定。
- 排查端口占用：残留 testbed 进程会占随机端口；`18080` 被占时用 `Get-NetTCPConnection -State Listen` + `Stop-Process`。
